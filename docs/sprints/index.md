# 스프린트

## 운영 방식

3인 팀의 개발은 Linear로 운영합니다. 구조는 개발 시작 전에 문서("MVP 작업 분해 및 Cycle 운영안")로 확정했습니다.

| Linear 단위 | 용도 |
|:---|:---|
| Project | **기능 단위** — 01. 인증 ~ 12. 백오피스, photoselect 모듈 등 |
| Issue | 직군별 작업 (Sub-issue = 세부 구현 단위) |
| Label | **직군 구분** — FE / BE / INFRA / AI |
| Cycle | 스프린트 — 주 단위, 월요일 시작 |

직군을 Team이 아니라 Label로 구분하는 이유도 문서에 남아 있습니다 — 3인 팀에서 Team을 나누면 이슈 식별자와 사이클이 분리되어 관리 비용만 늘기 때문입니다. 운영안 초안은 2주 스프린트였지만 실제로는 **주 단위 사이클**로 정착했습니다.
