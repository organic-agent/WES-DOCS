# ADR-002 — 원본이 아니라 파생본을 보여준다

| | |
|:---|:---|
| 상태 | 채택 (파생본 규격은 부분 구현) |
| 시기 | 2026-07-27 (ImageLoad PoC 3차 측정 결론) |

## 맥락

뷰어에서 사진을 연속으로 넘길 때 40MB급 원본을 그대로 로드하면 어떤 클라이언트 정책(디바운스·프리페치)으로도 쓸 만한 경험이 나오지 않는다. RAW·HEIC는 애초에 브라우저가 그리지 못한다.

## 결정

열람은 **표시용 파생본**을 기본으로 하고 원본은 다운로드·줌 진입 시에만 로드한다. 클라이언트는 **썸네일 선로드(그리드 캐시 재사용) + 프리페치(디코드 선행) + 디바운스**를 조합해 적용한다.

## 근거

[ImageLoad PoC](../tech/poc.md) 82런 측정 : 파생본 전환만으로 메인 표시 3.1초 → 414ms(7.5배), 프리페치 결합 시 103ms에 p95 안정화, 700ms 연타 완료율 0% → 100%, 디바운스+프리페치 조합으로 낭비 전송 0 수렴. 디바운스 단독은 완료율을 깎는 역효과가 측정으로 확인됐으므로 **반드시 프리페치와 세트로** 적용한다.

## 결과

- 파생본 생성을 임베딩 잡에 통합했다([ADR-007](adr-007-embedder-single-job.md)) — 어차피 디코딩한 이미지를 재활용한다.
- 프론트엔드 그리드·뷰어는 파생본 URL과 "미리보기 준비 중" 상태를 쓴다.
- 현 구현은 임베딩 리사이즈(1024px)를 재사용한 JPEG 단일본(장당 약 200KB)이다. 남은 병목이 네트워크(276ms)로 측정된 만큼, PoC가 권고한 2단 체계(512px 썸네일 + 2048px WebP)는 CDN·AVIF와 묶어서 진행한다.
