# ADR-007 — 임베딩·파생본·EXIF를 한 번의 잡으로

| | |
|:---|:---|
| 상태 | ADR-010으로 대체 |
| 시기 | 2026-08 (embedder 구현) |

## 맥락

{: .warning }
이 문서는 서버 내 embedder를 운용하던 2026-08의 역사 기록이다. 현재 모델 실행은 외부 AI 워커 저장소가 담당한다. 현행 경계는 [ADR-010](adr-010-external-ai-worker.md)을 따른다.

[ADR-001](adr-001-presigned-direct-upload.md)의 결과로 앱 서버는 이미지 바이트를 만지지 않는다. 그런데 이미지를 실제로 열어야만 가능한 일이 세 가지 있다 — 임베딩 계산, 브라우저용 미리보기 파생본 생성(HEIC는 브라우저가 못 그린다), EXIF 추출(촬영 시각·카메라·노출 정보). 각각을 별도 잡으로 만들 것인가.

## 결정

**한 번의 잡(embedder Lambda)에 전부 얹는다.** 임베딩을 하려면 어차피 S3에서 원본을 받아 HEIC를 디코딩하고 EXIF 회전을 굽고 크기를 줄여야 하는데, 그 결과가 그대로 브라우저가 그릴 수 있는 이미지다. 남은 일은 JPEG 인코딩과 PUT 하나뿐이므로 별도 잡으로 빼지 않는다 — 빼면 같은 이미지를 두 번 받아 두 번 디코딩하게 된다. EXIF도 이미 열어 둔 원본에서 태그만 훑으면 되므로 같은 UPDATE에 얹는다.

## 근거

- S3 GET과 이미지 디코드가 잡 비용의 대부분이므로, 잡을 나누면 그 비용이 곱해진다.
- EXIF는 회전·축소 **전의** 원본에서 읽어야 한다 (변환 후에는 Orientation 태그가 지워지고 크기도 원본이 아니다). → 디코드 직전 시점을 가진 이 잡이 유일하게 올바른 위치다.

## 결과

- 갤러리당 1회 비동기 호출로 임베딩·파생본·EXIF가 함께 채워진다. 사진당 호출이 없으므로 호출 오버헤드도 없다.
- 대신 **부분 실패 격리**가 필수가 됐다 — 파생본 실패(`previewsFailed`)와 EXIF 실패(`metadataFailed`)는 임베딩을 죽이지 않고 별도 목록으로 반환한다. 실패 목록이 곧 운영 진단 신호다 (예 : 파생본만 전량 실패 → 임베딩이 아니라 S3 쓰기 권한 문제).
- 재실행 안전(`embedding IS NULL` 대상 선별) 덕에 실패 후 재호출이 항상 안전하다. 전체 흐름은 [AI 파이프라인](../tech/ai-pipeline.md) 참고.
