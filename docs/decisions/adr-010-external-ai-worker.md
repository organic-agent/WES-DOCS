# ADR-010 — 외부 AI 워커 경계

| | |
|:---|:---|
| 상태 | 채택 |
| 시기 | 2026-09 |

## 맥락

제품 서버와 모델 런타임을 한 저장소와 배포 단위로 묶으면 JVM API 릴리스가 모델 의존성·GPU/배치 환경과 결합한다. 장애 책임과 스키마 소유권도 흐려진다.

## 결정

WES-Server는 분석·분류·추천 작업의 상태와 입출력 계약을 관리한다. 모델 실행 코드는 별도 AI 워커 저장소가 소유한다. 제품 서버가 외부 분석 실행을 요청하고 상태를 관측한다. 단계별 호출·heartbeat 계약은 서버에 준비되어 있지만 현재 기본값은 `lambda-reports-stage=false`이고 AI main은 Score→Categorize를 직접 호출한다. 현재 방식과 준비된 계약은 [AI 파이프라인](../tech/ai-pipeline.md)에서 구분한다. 외부 분석 결과를 카테고리로 만드는 작업은 서버가 수행한다. 갤러리 제약의 범위는 기능별 ERD로 구분한다.

## 결과

- 서버 문서에서 Python Lambda와 모델 코드를 서버 내부 도메인으로 설명하지 않는다.
- 제품 배포와 모델 배포를 독립시킨다.
- 워커 구현 SHA는 별도 저장소에서 관리한다. AI `d256875`의 소스를 확인했으며 운영 워커 배포 SHA·단계 보고 적용은 별도 검증 대상이다.
- [AI 파이프라인](../tech/ai-pipeline.md)과 기능별 ERD가 저장 계약을 정의한다.
