# 사업 전략

수익 구조와 예상 위험에 대한 기획 가설이다. 아래 가격·아카이빙·개인정보 처리 방향을 현재 구현이나 확정 운영 정책으로 해석하지 않는다.

## 수익 모델

[기획 피벗](studio-workflow.md)에 따라 부부에게 직접 과금하지 않고, **사진 업체를 경유해 비용을 청구하는 B2B2C 구조**를 우선으로 삼는다.

- **B2B 구독** — 사진작가·업체가 플랫폼을 사용하고, 부부 1쌍당 수수료·추가금이 업체를 통해 청구
- **부가 서비스** — 모바일 청첩장, 보정 요청 중개 수수료

사업화는 베타 운영과 촬영 업체 파일럿에서 업무 절감 효과를 확인한 뒤 유료 전환을 판단한다.

---

## 예상 위험과 대응

| 영역 | 위험 | 대응 |
|:---|:---|:---|
| 개발 | 대량 업로드·처리 시 서버 과부하 | Presigned URL 직접 업로드로 앱 서버 부하를 분리하고 외부 AI 워커를 독립 운영 |
| 개발 | AI 분류·추천의 부분 실패 | 사진별 결과와 실패 코드를 노출하고 사람이 카테고리·셀렉 초안을 수정 |
| 관리 | 3인 팀 역할 분산 병목 | 기능 단위 스프린트, 주간 싱크 미팅으로 병목 조기 식별 |
| 상용화 | 촬영 업체의 플랫폼 도입 저항 | 초기 무료 플랜 + B2B2C 채널 홍보 |
| 상용화 | 초기 사용자 확보 어려움 | 웨딩 커뮤니티·인스타그램 타겟 광고 + 촬영 업체 경유 간접 유입 |
| 비용 | AWS S3 비용이 용량·건수에 비례해 급증 | 용량 티어·장기 보관 정책 검토. 현재 일반 삭제의 7일 휴지통·purge와 구분 |
| 법률 | 이미지 임베딩 데이터의 개인정보보호법 저촉 가능성 | 처리 목적·보관·삭제 정책 확정 필요. 현재 photo_analysis는 분석 결과를 저장하며 완료 즉시 임베딩을 파기하지 않음 |

정량 목표는 파일럿 측정 전까지 고정하지 않는다. 처리 시간, 셀렉 완료율, 보정 재요청률의 정의와 기준선을 먼저 확정한다.
