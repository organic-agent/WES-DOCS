# 문제 정의 — 셀렉 피로와 갈등

## 셀렉의 밤

웨딩 촬영을 마친 커플이 집에 돌아온다. 스튜디오에서 받는 것은 보정된 완성본이 아니라 많은 원본 사진이다. 이 중에서 최종 보정·납품할 사진을 직접 골라 스튜디오에 알려줘야 한다. 이것이 "셀렉"이다.

셀렉이 실제로 흘러가는 모습을 마케팅 시안을 만들며 시간대별로 정리했다.

> 오후 9:07 — "이것도 예쁜데?"
> 오후 11:48 — "아까 사진 다시 보자"
> 오전 2:13 — "첫 장부터 다시 볼까?"
> 몇 시간째 보는 중, 결정한 건 없음.
> "나 이제 다 똑같아 보여."
> "자기야 이게 나아, 이게 나아?" / "어.. 왼쪽?" / "아깐 오른쪽이라며, 집중 안 해?"

밤 9시에 설렘으로 시작한 셀렉이 새벽 2시에 말다툼으로 끝난다. 그래서 서비스의 방향을 한 문장으로 정했다 — **"사진 셀렉, 싸우지 말고 EasySelect."**

---

## 문제의 구조

이 밤이 반복되는 이유는 세 가지다.

- **후보가 줄지 않는다** : 수천 장이 아무 구조 없이 나열되어 있고, 비슷한 컷이 수십 장씩 있어도 도구는 그것을 모르므로 "이것도 예쁜데?"가 쌓일수록 후보는 늘기만 한다.
- **앞으로 가지 못하고 되돌아간다** : 비교할 기준이 없으면 기억에 의존하게 되고, 기억이 흐려지면 처음으로 돌아간다. → "아까 사진 다시 보자"가 "첫 장부터 다시 볼까?"로 커진다.
- **피로가 갈등이 된다** : 셀렉은 혼자 하는 결정이 아니라 두 사람의 합의라서, 선택 피로가 쌓인 상태에서 의견이 갈리면 사진 고르기가 감정 소모로 바뀐다.

작가 쪽에도 대응되는 문제가 있다. 셀렉이 끝나도 보정 요청이 "얼굴 자연스럽게 해주세요" 같은 모호한 문장으로 도착하고, 결과물이 기대와 다르면 컴플레인이 된다. 그래서 기획서에 보정 요청 기능의 목적을 이렇게 못박았다.

> 목적은 모호한 요구를 사전에 합의 가능한 형태로 정리하여 컴플레인을 줄이고 사진작가의 처리 편의를 높이는 것이다.
> — 제품 기획서 §2 (보정 요청)

## 접근 — 대신 골라주지 않고, 고르기 쉽게

EasySelect의 답은 "AI가 골라드립니다"가 아니다. 세 가지 방식으로 고르는 일 자체를 가볍게 만든다.

| 문제 | EasySelect의 접근 |
|:---|:---|
| 후보가 줄지 않는다 | **컨셉·세부 카테고리** — AI 초안을 사람이 고치고 미분류·실패 사진까지 확인 |
| 되돌아가게 된다 | **공동 셀렉과 별점** — 선택, 작성자와 정렬 순서를 서버에 저장해 진행 상태를 보존 |
| 피로가 갈등이 된다 | **AI 1차 셀렉과 게스트 협업** — 수동 선택을 유지한 채 남은 자리만 채우는 수정 가능한 초안, 그리고 지인의 좋아요·댓글로 결정 부담 분산 |

{: .note }
AI는 수정 가능한 초안을 만들 뿐 자동으로 제출하거나 최종 판단을 대신하지 않는다. 현재 모델 실행은 [외부 AI 워커](../decisions/adr-010-external-ai-worker.md)가 담당한다.
