# 문제 정의 — 셀렉 피로와 갈등

## 셀렉의 밤

웨딩 촬영을 마친 커플이 집에 돌아옵니다. 스튜디오에서 받은 것은 완성된 앨범이 아니라 원본 사진 전체 — 많게는 수천 장입니다. 이 중에서 앨범에 들어갈 수십 장을 부부가 직접 골라 작가에게 알려줘야 합니다. 이것이 "셀렉"입니다.

셀렉이 어떻게 흘러가는지는 내부 마케팅 시안에 시간대별로 기록되어 있습니다.

> 오후 9:07 — "이것도 예쁜데?"
> 오후 11:48 — "아까 사진 다시 보자"
> 오전 2:13 — "첫 장부터 다시 볼까?"
> …몇 시간째 보는 중. 결정한 건 없음.
> "나 이제 다 똑같아 보여."
> "자기야 이게 나아, 이게 나아?" / "어.. 왼쪽?" / "아깐 오른쪽이라며, 집중 안 해?"

밤 9시에 설렘으로 시작한 셀렉이 새벽 2시에 말다툼으로 끝납니다. 이 시안의 엔드카드가 서비스의 방향을 한 문장으로 요약합니다 — **"사진 셀렉, 싸우지 말고 EasySelect."**

## 문제의 구조

이 밤이 반복되는 이유를 세 가지로 정리했습니다.

**후보가 줄지 않는다.**
수천 장이 아무 구조 없이 나열되어 있습니다. 비슷한 컷이 수십 장씩 있지만 도구는 그것을 모릅니다. "이것도 예쁜데?"가 쌓일수록 후보는 늘기만 합니다.

**앞으로 가지 못하고 되돌아간다.**
비교할 기준이 없으니 기억에 의존하게 되고, 기억이 흐려지면 처음으로 돌아갑니다. "아까 사진 다시 보자"가 "첫 장부터 다시 볼까?"로 커지는 구조입니다.

**피로가 갈등이 된다.**
셀렉은 혼자 하는 결정이 아니라 두 사람의 합의입니다. 선택 피로가 쌓인 상태에서 의견이 갈리면, 사진 고르기는 감정 소모가 됩니다.

작가 쪽에도 대응되는 문제가 있습니다. 셀렉이 끝나도 보정 요청이 "얼굴 자연스럽게 해주세요" 같은 모호한 문장으로 도착하고, 결과물이 기대와 다르면 컴플레인이 됩니다. 기획서는 보정 요청 기능의 목적을 이렇게 명시합니다.

> 목적은 모호한 요구를 사전에 합의 가능한 형태로 정리하여 컴플레인을 줄이고 사진작가의 처리 편의를 높이는 것이다.
> — WES 제품 기획 §2 (보정 요청)

## 접근 — 대신 골라주지 않고, 고르기 쉽게

WES의 답은 "AI가 골라드립니다"가 아닙니다. 세 가지 방식으로 **고르는 일 자체를 가볍게** 만듭니다.

| 문제 | WES의 접근 |
|:---|:---|
| 후보가 줄지 않는다 | **유사 사진 스택** — 시각적 유사도로 비슷한 컷을 묶고, 5틱 슬라이더로 묶음 강도를 조절 |
| 되돌아가게 된다 | **비교 셀렉과 폴더 고정** — 나란히 비교하고, 정리한 구조를 폴더로 저장해 진행 상태를 보존 |
| 피로가 갈등이 된다 | **AI 1차 셀렉과 게스트 협업** — 수동 선택을 유지한 채 남은 자리만 채우는 수정 가능한 초안, 그리고 지인의 좋아요·댓글로 결정 부담 분산 |

{: .note }
AI가 무엇을 **하지 않는지**가 이 제품의 정체성입니다. 카테고리를 만들지 않고, 정상 사진을 버리지 않고, 취향을 학습하지 않고, 자동으로 제출하지 않습니다. 이 원칙이 어떻게 정해졌는지는 [피벗 — 카테고리에서 유사도로](pivot.md)에 있습니다.
